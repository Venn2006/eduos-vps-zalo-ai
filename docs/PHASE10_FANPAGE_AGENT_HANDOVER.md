# Phase 10: Fanpage Agent Foundation - Handover Document

## 1. Implementation Summary
The Phase 10 foundation implemented the following core capabilities for the Fanpage Agent:
*   **Facebook Webhook GET/POST Route:** Endpoint (`/api/webhooks/facebook`) handling Meta Graph API verification (GET) and inbound event processing (POST).
*   **X-Hub-Signature-256 Behavior:** Secure cryptographic verification of inbound webhooks using Node's native `crypto` module, enforcing payload integrity when `FACEBOOK_APP_SECRET` is configured.
*   **Facebook Inbound Message Storage:** Storage of inbound customer messages into the `FacebookConversation` model.
*   **Idempotency Behavior:** Safely prevents processing duplicate webhook deliveries via checking existing conversation messages.
*   **Tenant Resolution by FacebookPage:** Correctly associates incoming events to the appropriate tenant using the registered `FacebookPage` ID mapping.
*   **Fanpage AI Agent:** Core intelligent agent that classifies intent and drafts Vietnamese responses.
*   **AiSuggestion Draft Creation:** Agent recommendations are stored strictly as `AiSuggestion` records in the database.
*   **Lead/FollowUpTask Handoff:** Identifies potential hot leads from conversations, linking the conversation to a `Lead` record, and hands off to the CRM queue with a `FollowUpTask`.
*   **`/fanpage-inbox` UI:** An operational dashboard allowing staff to read messages and copy AI-generated drafts.
*   **Dashboard Fanpage Metrics:** Included foundational data fetchers to roll up fanpage metrics to the CEO dashboard.
*   **Tests Added:** Comprehensive unit tests validating webhook signature boundaries (missing/invalid signatures) and the core AI agent prompt/behavior logic.

## 3. API Contract (`/api/webhooks/facebook`)
*   **GET Webhook Verification:** Responds to Meta's `hub.challenge` providing `hub.verify_token` matches the server configuration.
*   **POST Webhook Payload Shape:** Expects Meta's standard payload format (`{ object: "page", entry: [...] }`).
*   **Response Behavior:** Returns `200 EVENT_RECEIVED` immediately upon queuing/processing to prevent Meta retry floods. Duplicate webhook event IDs are ignored cleanly.
*   **Signature Behavior:**
    *   **With `FACEBOOK_APP_SECRET`:** Rejects requests with missing signatures (`401`) or invalid signatures (`403`). Valid signatures proceed normally.
    *   **Without `FACEBOOK_APP_SECRET` (Local Dev):** Emits a console warning but allows the payload to process to ease local testing.

## 5. Safety Rules
*   **No Facebook Graph Send API:** There is absolutely no code pushing messages to Facebook.
*   **No Auto-Send / No Bulk DM:** The agent operates completely passively.
*   **No Scraping:** Relies strictly on the official Webhook boundary.
*   **Drafts Only:** AI replies are merely `AiSuggestion` database records.
*   **Manual Send Flow:** Staff must manually send messages from the official Fanpage UI or copy-paste from EduOS.
*   **Approval Required:** Any sensitive operational replies generated by the AI require staff review and manual approval.

## 6. Known Limitations
*   **Phase 10 is Foundation Only:** The implementation establishes the infrastructure but does not comprise the finished feature set.
*   **TrialBooking Creation Not Wired:** The schema supports it, but the AI agent does not currently extract or persist automatic trial bookings from chat.
*   **Browser Verification Not Performed:** UI components (`/fanpage-inbox`) lack manual or Playwright browser testing validation.
*   **No Real Meta Graph Integration:** Beyond the incoming webhook boundary, there is no bidirectional Sync/Send integration yet.
*   **No Approval/Send Adapter:** No unified adapter exists yet to handle state transitions from "Approved" to actually "Sent".
*   **No Production App Secret:** No secret is configured by default unless the environment explicitly injects `FACEBOOK_APP_SECRET`.
*   **UI is Draft Display Only:** The UI flow represents viewing and copying a draft, not a real outbound send action.
